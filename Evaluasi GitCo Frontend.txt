## SECTION 1: SYSTEMIC HEALTH & EXECUTIVE SUMMARY

### 1.1 Platform Identity

MLPHoma adalah **Construction Management Information System (CMIS)** berbasis SPA (Single Page Application) yang mengintegrasikan 9+ domain modul: AHSP → RAB → WBS → Timeline/CPM → RAP → Curva-S → Cash Flow → Supply Chain → Finance. Stack: **React 18.3 + TypeScript 5.9 + Zustand 5 + Supabase + Tailwind/shadcn/ui**, di-deploy ke Vercel via HashRouter.

### 1.2 Macro Health Score

| Dimensi | Score | Keterangan |
|---|---|---|
| **Arsitektur Teknis** | 🟡 65/100 | Layering solid secara teori; implementasi partial — 8 file melanggar layer boundary langsung akses Supabase |
| **State Management** | 🟡 60/100 | 16 Zustand stores; 5 store tidak punya `loading`/`error` state; hanya 4/16 punya cached getter |
| **Design System Maturity** | 🟡 68/100 | shadcn/ui + Radix = solid foundation; tapi `components/change` dan `components/change-order` duplikat tujuan; belum ada shared `DataTable` primitive |

| **Nielsen Heuristics** | 🟡 58/100 | Visibility of system status lemah (5/16 store tanpa loading state); Error prevention ada Zod tapi error pipeline tidak konsisten di UI layer |

| **Test Coverage** | 🔴 42/100 | 11/27 service tested; 16 service untested termasuk `supplyChainService` (335 baris, budget locking) dan `progressBillingService` |

**Overall Enterprise Readiness: 58/100 — Foundation Solid, Execution Gap Signifikan**

### 1.3 Critical Finding Summary (Top-5)

> **CF-01 🔴 Layer Boundary Violation:** 8 file mengakses Supabase langsung di UI/Store layer — ini menciptakan *silo data* dan menghancurkan kemampuan testing, caching, dan error tracing.

> **CF-02 🔴 WCAG AA Failure pada Touch Targets:** Class `.control-compact` (h-8 = 32px) dan `.density-compact` (text-xs) digunakan secara luas untuk tabel engineering — ini kritis bagi Field Engineer yang mengoperasikan tablet di lapangan.

> **CF-03 🟠 State Synchronization Gap:** Update di `rabStore` tidak otomatis me-trigger re-kalkulasi di `curvaSStore`. Jika PM mengubah volume RAB, Curva-S tidak live-update — melanggar prinsip SSOT.

> **CF-04 🟠 Navigation Architecture Dual-Source:** `NAV_ITEMS` masih hardcoded di `AppShell.tsx` (15 items) dengan `ModuleKey` di `routes.ts` (24 keys) — 9 modul "ghost" yang tidak visible dan menciptakan confusion wayfinding.

> **CF-05 🟡 Cognitive Overload pada Data-Dense Modules:** Tabel RAB dan Gantt merender semua data sekaligus tanpa progressive disclosure. Berdasarkan Hick's Law, user dihadapkan dengan 10+ column + action toolbar secara simultan.

### 4.3 System Integration Logic (Frontend)

#### A. Cross-Store State Synchronization Map

```typescript
/**
 * MANDATORY CROSS-STORE SUBSCRIPTIONS
 * Implementasikan di src/store/storeSubscriptions.ts
 * Di-inisialisasi sekali di App.tsx setelah semua stores loaded
 */

// 1. AHSP price update → invalidate RAB cached prices
ahspStore.subscribe(
  (s) => s.items,
  (items) => rabStore.getState().invalidatePriceCache()
)

// 2. RAP update → recalculate Curva-S
rapStore.subscribe(
  (s) => s.planData,
  (planData, prevPlanData) => {
    if (planData !== prevPlanData) {
      const projectId = projectStore.getState().activeProjectId
      if (projectId) curvaSStore.getState().recalculateFromRAP(projectId)
    }
  }
)

// 3. RAB item update → propagate to linked Timeline task cost
rabStore.subscribe(
  (s) => s.items,
  () => timelineStore.getState().syncTaskCostsFromRAB()
)

// 4. WBS deletion guard → check timeline dependencies
// Implemented in wbsStore.removeItem() as pre-condition check
```

### 4.4 Feature Epics & User Stories

#### EPIC 1: SSOT Pipeline — RAB ↔ Timeline ↔ RAP Real-Time Sync

**User Story 1.1 — PM: Budget-to-Schedule Traceability**
> *"Sebagai Project Manager, saya ingin ketika saya mengubah volume RAB item, nilai tersebut langsung terefleksi di Timeline task cost dan RAP monthly distribution TANPA harus refresh manual, sehingga saya selalu melihat dampak perubahan budget secara real-time."*

**Acceptance Criteria:**
- [ ] Update volume di `rabStore` → `timelineStore.syncTaskCostsFromRAB()` dipanggil otomatis dalam <500ms
- [ ] Update timeline schedule → `rapStore.recalculateDistribution()` dipanggil otomatis
- [ ] `curvaSStore` merender updated S-Curve dalam <2s setelah RAP berubah
- [ ] Toast notification: *"RAB diperbarui — Timeline & RAP tersinkronisasi ✓"*
- [ ] Tidak ada manual refresh yang diperlukan

**User Story 1.2 — FE: Field Progress Update → EVM Impact**
> *"Sebagai Field Engineer, saya ingin update progress pekerjaan di tablet lapangan langsung mengupdate nilai Earned Value di Curva-S, sehingga kantor bisa melihat performa aktual proyek dalam hitungan menit, bukan hari."*

**Acceptance Criteria:**
- [ ] Input progress (%) di `FieldTasks` → trigger `curvaSStore.updateActualProgress(taskId, progress)`
- [ ] Semua form input di `FieldTasks` menggunakan `size="field"` (48px touch target)
- [ ] Offline: progress update masuk ke `offlineQueueStore`, sync saat online kembali
- [ ] Sync status indicator: *"3 updates pending sync — Tap to retry"* (dismissible banner)
- [ ] Berhasil sync → push notification / toast *"Progress terkirim ke server ✓"*

**User Story 1.3 — FC: Three-Way Match dengan Alert Otomatis**
> *"Sebagai Finance Controller, saya ingin menerima notifikasi otomatis ketika nilai Invoice dari vendor melebihi 5% dari nilai PO terkait, sehingga saya dapat segera melakukan verifikasi sebelum proses pembayaran."*

**Acceptance Criteria:**
- [ ] `ThreeWayMatch` logic dipindahkan ke `financeService.ts` (tidak ada direct Supabase di component)
- [ ] Rule engine: `|invoiceAmount - poAmount| / poAmount > 0.05` → trigger `notificationStore.addAlert()`
- [ ] Alert tampil di sidebar notification badge (real-time via Supabase Realtime)
- [ ] Alert modal menampilkan: PO#, Invoice#, PO Amount, Invoice Amount, Variance%, Action buttons (Approve Variance / Reject / Request Clarification)
- [ ] Audit trail: setiap action tercatat di `auditService.ts`

#### EPIC 2: WCAG AA Accessibility Refit

**User Story 2.1 — FE: Mobile-First Touch Target Compliance**
> *"Sebagai Field Engineer yang menggunakan tablet Android di lokasi konstruksi, saya ingin semua tombol dan input memiliki ukuran yang cukup besar sehingga dapat dioperasikan dengan akurasi tinggi meskipun menggunakan sarung tangan kerja atau dalam kondisi cahaya terik."*

**Acceptance Criteria:**
- [ ] Semua interactive elements di `FieldTasks` module: minimum `h-11` (44px)
- [ ] Semua form inputs di mobile view: `h-12` (48px) + `text-sm` (14px) minimum
- [ ] Remove `.control-compact` dari `FieldTasks` dan semua mobile-facing components
- [ ] Automated axe-core accessibility test dalam CI — tidak boleh ada WCAG AA violation pada release
- [ ] Contrast ratio: semua text/background kombinasi ≥ 4.5:1 (AA), atau ≥ 7:1 (AAA untuk critical data)

**User Story 2.2 — PM: Keyboard Navigation Enterprise Grade**
> *"Sebagai Project Manager yang menggunakan aplikasi via keyboard untuk efisiensi, saya ingin dapat menavigasi seluruh tabel RAB, melakukan edit cell, dan submit tanpa pernah menyentuh mouse."*

**Acceptance Criteria:**
- [ ] `Tab` → navigasi antar cell di tabel RAB (menggunakan `@tanstack/react-virtual` + keyboard handler)
- [ ] `Enter` → enter edit mode pada focused cell
- [ ] `Escape` → cancel edit
- [ ] `Ctrl+S` → save all pending changes
- [ ] `Cmd+K` → Global Command Palette accessible dari mana saja
- [ ] Focus ring visible: minimum 2px solid, dengan 2px offset (sudah dikonfigurasi di Tailwind config ✅)

---

#### EPIC 3: Design System Consolidation — Atomic Component Library

**User Story 3.1 — Dev Team: Shared DataTable Primitive**
> *"Sebagai developer yang membuat fitur baru di modul Supply Chain, saya ingin menggunakan satu komponen DataTable yang sudah menangani sorting, filtering, loading skeleton, error state, dan virtual scrolling, sehingga saya tidak perlu mengimplementasikan ulang hal yang sama dari awal."*

**Acceptance Criteria:**
- [ ] `src/components/shared/DataTable.tsx` tersedia dengan interface standar (loading, error, emptyState, virtualized)
- [ ] Digunakan oleh minimum 5 modul setelah release (RABTable, Timeline list, Supply Chain, AHSP, DKH)
- [ ] Virtualization otomatis aktif untuk datasets > 100 rows (menggunakan `@tanstack/react-virtual` yang sudah ada di dependencies ✅)
- [ ] Storybook (atau Vitest snapshot) untuk setiap state: loading, error, empty, populated, virtualized

## EXECUTIVE RECOMMENDATION SUMMARY

> **MLPHoma memiliki fondasi arsitektural yang lebih baik dari rata-rata ConTech startup pada fase yang sama.** Pipeline kalkulasi AHSP→RAB→RAP tersentralisasi, Zustand stores terdefinisi dengan baik secara domain, dan Supabase RLS sudah diterapkan. Namun, **gap antara arsitektur ideal dan implementasi aktual menciptakan risiko operasional nyata:**

1. **🔴 Immediate (< 1 sprint):** Perbaiki dark mode WCAG contrast (`--destructive`). Ini 30 menit pekerjaan tapi membuat aplikasi legally accessible.

2. **🔴 Sprint 1-2:** Selesaikan layer boundary enforcement (8 file offender) + implementasikan cross-store subscriptions (RAP→CurvaS). Ini adalah prasyarat mutlak sebelum menambah fitur Enterprise baru apapun.

3. **🟠 Sprint 2-3:** Implementasikan shared `DataTable` primitive + standardisasi touch targets untuk Field Engineer. ROI tertinggi untuk user satisfaction di lapangan.

4. **🟠 Sprint 3-4:** Naikkan service test coverage dari 42% → 100%. Tanpa ini, refactoring apapun berisiko tinggi.

5. **🟡 Sprint 5-6:** Navigation hierarchy redesign + Design System consolidation. Ini yang akan membawa MLPHoma dari "functional" ke "enterprise-grade UX".

**Final Score:** Platform ini adalah **diamond in the rough** — dengan 12 minggu eksekusi disiplin mengikuti roadmap di atas, MLPHoma dapat mencapai Enterprise Readiness Score **85+/100** dan siap untuk ekspansi ke multi-project portfolio management dan integrasi ERP eksternal.
